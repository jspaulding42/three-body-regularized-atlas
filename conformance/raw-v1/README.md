# Raw-v1 seed conformance corpus

This directory is a versioned, implementation-neutral **seed**, not the
complete raw-v1 conformance corpus required for an independent verifier.  Its
two baseline cases are copied from the checked-in v0.3 review bundle, and
their expected facts are transcribed from the corresponding checked-in replay
transcripts.
No expectation in this seed was generated by importing the Python checker.

## Outcomes

Every case has two distinct stages:

1. `expected_parse_outcome = "REJECT"` means the input is not an admissible
   canonical raw-v1 byte payload.  Rejection has no replay result, no certified
   prefix, and `expected_replay_outcome` and `facts` must both be `null`.
2. `expected_parse_outcome = "ACCEPT"` means parsing succeeds.  Replay then
   returns exactly one of:
   - `CERTIFIED_TO_T`: every decisive obligation and the requested final-width
     bound succeeds;
   - `UNRESOLVED`: the evidence does not prove the requested theorem, although
     a certified prefix or retained frontier may still be present.

`UNRESOLVED` is not parser rejection and is not a claim that the trajectory or
a stronger certificate does not exist.

The neutral expectation format is defined by
[`expected-result.schema.json`](expected-result.schema.json).  Each accepted
case lists a compact subset of replay facts that a verifier must reproduce.
Unlisted transcript diagnostics are outside this seed's comparison surface.
Exact rationals are objects with canonical decimal-string `numerator` and
positive `denominator` fields.  File paths stored in expectations and the
manifest are relative to this `conformance/raw-v1/` corpus root.

## Seed cases

- `success`: canonical five-segment evidence with one ordinary bridge followed
  by LC passages for `(0,1)`, `(0,2)`, `(1,2)`, and a `(0,1)` revisit.  Expected
  replay outcome: `CERTIFIED_TO_T`.
- `failed-revisit`: the corresponding structured-failure case.  Four segments
  certify; the revisit exit fails complete projection containment and retains
  a certified lifted LC-right frontier.  Expected outcome: `UNRESOLVED`.

### Byte-parser rejection tranche

Every rejection fixture is a single described mutation of
`inputs/success.raw.json`.  `JSON-valid` below means `jq` accepts the JSON
syntax; it does not imply canonical raw-v1 admissibility.

| Case | Isolated mutation | JSON-valid | Expected |
|---|---|---:|---|
| `reject-leading-whitespace` | prepend one space | yes | `REJECT` |
| `reject-trailing-newline` | append one LF | yes | `REJECT` |
| `reject-duplicate-outer-key` | duplicate `certificate_id` | yes | `REJECT` |
| `reject-unsorted-outer-keys` | swap first two outer members | yes | `REJECT` |
| `reject-alternate-real-spelling` | spell binary64 `0.1` as `0.10000000000000001` | yes | `REJECT` |
| `reject-unknown-outer-field` | add sorted `zz_unknown` member | yes | `REJECT` |
| `reject-missing-outer-field` | remove required `source` | yes | `REJECT` |
| `reject-wrong-outer-scalar-class` | spell integer schema version as real `1.0` | yes | `REJECT` |
| `reject-unknown-segment-tag` | change first tag to `ordinary_bridge_v2` | yes | `REJECT` |
| `reject-decoded-duplicate-unicode-key` | add `\u0073ource`, decoded duplicate of `source` | yes | `REJECT` |
| `reject-nonfinite-token` | replace target real with `NaN` | no | `REJECT` |
| `reject-overflow-real` | replace target real with `1e400` | yes | `REJECT` |
| `reject-invalid-utf8` | replace one identifier byte with `0xff` | no | `REJECT` |
| `reject-lone-surrogate` | place lone `\ud800` escape in identifier | no | `REJECT` |
| `reject-wrong-pair-length` | shorten first LC pair to `[0]` | yes | `REJECT` |
| `reject-wrong-interval-length` | shorten initial parameter interval to one endpoint | yes | `REJECT` |

The canonical base has no trailing newline.  All rejection fixtures that must
preserve this property were generated mechanically from its bytes because
`apply_patch` cannot create a text file without a final newline.  The invalid
UTF-8 fixture likewise requires binary generation.  The intentional
trailing-newline fixture was recreated through `apply_patch`.  Each expectation
records the exact operation, minimality claim, syntax classification, base
hash, and generation method; the manifest binds the resulting bytes.

The two `.raw.json` baseline files in `inputs/` are byte-for-byte copies of the
v0.3 raw artifacts, including their required lack of a trailing newline.  Their
SHA-256 hashes therefore equal their theorem-evidence hashes.  The rejection
fixtures are derived mutations, not artifact copies.  `manifest.json` binds
every other file in this corpus.  It cannot include its own hash without a
self-reference; this exclusion is explicit in the manifest.

## Provenance and limits

The only source evidence is:

```text
artifacts/v0.3.0-review/planar-chain/success.raw.json
artifacts/v0.3.0-review/planar-chain/success.replay.json
artifacts/v0.3.0-review/planar-chain/failed-revisit.raw.json
artifacts/v0.3.0-review/planar-chain/failed-revisit.replay.json
```

This seed does not repair or strengthen v0.3 semantics.  In particular, it
must not be treated as independent confirmation of the source transcripts.

A complete corpus still needs, at minimum:

- ordinary-only chains, including the empty and multi-bridge cases;
- each canonical LC pair `(0,1)`, `(0,2)`, and `(1,2)` in isolation;
- successes and failures at every root, fold, LC-entry, LC-tube, LC-exit,
  fixed-time, final-enclosure, and width boundary;
- systematic mutations at every nested record boundary, including additional
  wrong tags/types/shapes, namespace collisions, mass/endpoint/gauge mutations,
  and paired cases proving which defects parse but become `UNRESOLVED`;
- numeric boundary cases for signed zero, subnormals, maximum finite binary64,
  overflow, decimal halfway rounding, exponent spellings, exact dyadics,
  interval endpoints, `nextafter`, square root, exponential, and Gronwall
  arithmetic; and
- cross-implementation fixtures produced and checked in two clean
  environments after the independent verifier exists.

## Validation

Validation requires no project imports:

```bash
jq empty conformance/raw-v1/expected-result.schema.json \
  conformance/raw-v1/expectations/*.json \
  conformance/raw-v1/manifest.json
shasum -a 256 conformance/raw-v1/inputs/* \
  conformance/raw-v1/expectations/*.json \
  conformance/raw-v1/README.md \
  conformance/raw-v1/expected-result.schema.json
```
