# v0.4 independent-verification release gates

## Audit basis and decision

This audit uses the v0.3 planar-chain baseline at commit
`a51b5d9a1d6c17986b9d1e7866497ec004b04e4a` and the public GitHub release
metadata checked on 2026-07-17. It does not infer a tag-protection rule or
external archive when no corresponding record is available. During this
audit,

```bash
python scripts/certify_repeated_planar_chain.py verify-bundle
python -m pytest -q tests/test_planar_chain_review_artifact.py
```

both exited successfully in the recorded local environment.

The strict result is **not ready for an independent-verification release**:
five of the ten gates below pass, and five fail. A passing gate means only the
precise property stated for that gate. In particular, same-implementation
replay does not become independent verification by passing the replay,
determinism, mutation, or trust-inventory gates.

## Pass/fail checklist

- [ ] **FAIL — Immutable release identity and archival record.**

  **Pass condition:** the source tree, raw evidence, replay outputs, manifest,
  and paper are bound to one annotated release tag at the final release commit;
  repository metadata records a durable content-addressed archive or DOI; and
  the archive exposes checksums that can be compared with the repository.

  **Observed evidence:** the public GitHub prerelease
  [`v0.3.0-review`](https://github.com/jspaulding42/three-body-regularized-atlas/releases/tag/v0.3.0-review)
  exists and its release metadata targets the merged baseline commit
  `a51b5d9a1d6c17986b9d1e7866497ec004b04e4a`. The local clone has not fetched
  that tag, and neither the remote metadata inspected here nor the repository
  establishes a tag-protection rule. `CITATION.cff` names version
  `0.3.0-review` and the repository URL, but no DOI or durable archival
  identifier. The planar-chain manifest names base commit
  `ddb3b07554688dd9ba247251deaef202b98e6a45` and explicitly says that the
  artifact was added after that base commit; it therefore does not bind the
  complete released tree at `a51b5d9...` by itself.

  **Work required:** archive the v0.3 baseline durably and record its archive
  identifier and release-asset checksums. For v0.4, create the final tag only
  after all remaining gates pass, bind it to the exact release commit, publish
  that tagged tree in the archive, and verify a clean reconstruction from the
  archived record.

- [x] **PASS — Canonical raw-evidence hashes are published and checked.**

  **Pass condition:** every theorem-facing raw fixture has a published SHA-256
  digest, and the replay command recomputes the digest from canonical bytes
  before accepting the fixture.

  **Observed evidence:** `artifacts/v0.3.0-review/planar-chain/manifest.json`
  records and `verify_review_bundle(...)` recomputes these raw digests:

  - success:
    `ede15b0f35cf741f542a6cd260470a93ee5ff85dc5ae2371db1b88819b821f11`;
  - failed revisit:
    `c6830919726c22fbca6e45d5781b2465e54876bfa89c25bc26e97284ff918727`.

  The same manifest records transport hashes for both replay transcripts.
  This gate does not make the manifest immutable; that is the failed archival
  gate above. For v0.4, mirror both raw hashes in the independent conformance
  specification and archive metadata rather than relying on one mutable file.

- [x] **PASS — One-command fresh replay exists.**

  **Pass condition:** after dependencies are installed, one documented command
  checks payload hashes, strictly parses each raw fixture, freshly evaluates
  it, and compares the resulting transcript with the retained transcript.

  **Observed evidence:** the documented command

  ```bash
  python scripts/certify_repeated_planar_chain.py verify-bundle
  ```

  performs those checks for the success and failed-revisit fixtures and exits
  nonzero on `ReviewArtifactError`. It passed during this audit. The command
  imports `three_body_symmetry.planar_chain_review_artifact` and ultimately
  invokes `check_raw_planar_chain(...)`; it is therefore correctly described
  as same-implementation replay, not independent verification.

- [ ] **FAIL — Dependencies and build inputs are reproducibly pinned.**

  **Pass condition:** Python and every runtime, test, and build dependency are
  fixed to exact versions in a lock or equivalent reproducible environment
  description; fetched distributions or wheels are hash-pinned; and a clean
  bootstrap command installs only those inputs.

  **Observed evidence:** `pyproject.toml` requires only Python `>=3.10`, uses
  `setuptools>=68`, and leaves `numpy`, `scipy`, `sympy`, and `pytest` unpinned.
  The tree contains no dependency lock, hash-pinned requirements file,
  container recipe, or recorded wheel set. The artifact manifest reports one
  environment (`CPython 3.12.0`, NumPy 1.26.4, SciPy 1.13.1, SymPy 1.12), but
  `test_build_environment_is_informational_not_an_acceptance_gate` explicitly
  confirms that a different environment is accepted.

  **Work required:** add a hash-locked verifier environment, pin the Python
  implementation and platform assumptions, provide a clean bootstrap command,
  and keep informational producer dependencies separate from the minimal
  verifier dependency set.

- [ ] **FAIL — Replay is demonstrated in two isolated clean environments.**

  **Pass condition:** two independently provisioned environments install from
  the pins, run the one-command replay and conformance suite, and retain their
  platform/toolchain fingerprints and output hashes. At least one environment
  must not reuse the developer virtual environment or its installed packages.

  **Observed evidence:** the manifest records one environment. The determinism
  test launches two fresh processes, but both use `sys.executable`, the same
  source checkout, and the same installed packages. No CI workflow, container
  image, or second-environment result is retained in the repository.

  **Work required:** run the pinned verifier in two clean environments (for
  example Linux x86-64 and macOS arm64, or two separately built containers),
  archive both reports, and require agreement on status, first failure,
  theorem hashes, ledgers, and final/retained enclosures.

- [x] **PASS — Same-environment export and replay are deterministic.**

  **Pass condition:** repeated fresh processes in one fixed environment emit
  byte-identical canonical raw and replay payloads and reproduce the published
  theorem digest and semantic result.

  **Observed evidence:**
  `test_builder_and_export_are_deterministic_and_pin_success_theorem_sha`
  clears the candidate cache, rebuilds the fixtures, launches two exporter
  subprocesses, and requires byte equality for both raw files and both replay
  transcripts. It also pins the successful raw theorem digest. Canonical JSON
  uses sorted keys, compact separators, finite numbers, strict UTF-8, and no
  terminal newline. This gate is deliberately same-environment only; the
  failed two-environment gate covers cross-environment evidence.

- [x] **PASS — Representative malformed and mutated evidence fails closed.**

  **Pass condition:** automated tests reject noncanonical syntax, schema
  extension, nonfinite values, duplicate identities, theorem-relevant raw
  mutation, transcript forgery, manifest forgery, and cached-result or object-
  type substitution.

  **Observed evidence:** `tests/test_planar_chain_review_artifact.py` rejects
  duplicate JSON keys, leading whitespace, a terminal newline, nonfinite
  values, unknown fields, replay-payload tampering even after its transport
  hash is rewritten, and manifest theorem-digest tampering. The focused raw
  chain tests additionally reject unknown tags and fields, clock resets, mass
  changes, identifier collisions, raw/result snapshot mutation, altered gauge
  and clock ledgers, altered kernel identifiers, hostile equality objects, and
  result subclasses. These are implementation tests rather than a portable
  malformed-input corpus; portability remains part of the failed conformance
  gate.

- [x] **PASS — The current trusted primitives are explicitly inventoried.**

  **Pass condition:** the theorem document states the arithmetic, analytic,
  runtime, formula, and implementation assumptions on which acceptance rests,
  while the artifact identifies the versioned theorem-facing kernels.

  **Observed evidence:** the `Trusted kernel` section of
  `docs/raw-repeated-planar-continuation-chain-theorem.md` names Python
  `int`/`Fraction`, canonical JSON/SHA-256, rational polynomial arithmetic,
  outward binary64 interval primitives, the Newtonian and fourteen-dimensional
  LC formulas, ODE enclosure, uniqueness/constraint/projection/deck lemmas,
  containment, square-root cover, gauge, induction, clock, and fixed-time
  kernels. The artifact manifest pins the corresponding checker and kernel
  identifiers. The document also says that the current mixed exact/outward
  backend is not an independently audited arbitrary-precision backend.

  For v0.4, the second verifier must publish its own smaller source-level trust
  inventory, including exact source revision or file digests and every shared
  primitive. Passing this inventory gate is not evidence that the primitives
  have been independently proved correct.

## v0.4 release rule

Do not describe v0.4 as independently verified until all ten top-level gates
and every independent-verifier subgate are checked. Before that point, a
release may accurately say `same-implementation replay reproduced in pinned
environments`, but it must retain the existing independent-verifier nonclaim.
